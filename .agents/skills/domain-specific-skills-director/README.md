# Domain-Specific Skills Director

Domain-Specific Skills Director skill alag-alag industries (SaaS, E-commerce, AI/Agents, DevTools, Fintech, Healthcare, EdTech, AgriTech) ke according product architecture, user roles, critical workflows, information architecture, trust requirements, aur specialized UX patterns establish karti hai.

---

## 🧠 Ye Skill Kya Hai?

Ye skill ek senior product-domain architect, solution strategist, aur specialized UX analyst ki tarah operate karti hai. Iska core rule hai: **A fashion e-commerce store, an AI multi-agent workspace, a developer API platform, a healthcare portal, and a fintech dashboard should NOT be designed using the same product logic.**

---

## 🎯 Iska Main Kaam Kya Hai?

* **Domain Detection & Classification**: Product ko Primary Domain (core workflow) aur Secondary Domain (supporting features) mein classify karti hai across 22+ industry categories.
* **Product Format vs. Domain Analysis**: Domain (e.g. Healthcare) ko Format (e.g. Mobile App vs Dashboard vs Landing Page) se distinct rakh ke map karti hai.
* **User Role & Permission Mapping**: Administrator, Operator, aur Consumer roles ke distinct dashboards, permissions, aur actions define karti hai.
* **Critical Domain Workflows**: Step-by-step workflow mapping (e.g. AI Agent: Input → Reasoning → Tool Stream → Approval → Output).
* **Trust & High-Stakes Compliance**: High-trust domains (Finance, Healthcare, Legal) ke liye transparency, error prevention, audit trails, aur HIPAA/PCI-DSS rules establish karti hai.

---

## ⚡ Kab Use Hogi?

* Jab domain-heavy application (Fintech, Healthcare, DevTools, AI Agents, E-commerce) analyze ya build karni ho.
* Jab multiple user roles (Admin, Operator, End-user) ke workflows aur permissions map karne hon.
* High-trust requirements wale products mein safety, transparency, aur error recovery features design karte waqt.

---

## 📥 Isko Kya Input Chahiye?

* **Product Requirements**: Application ka main purpose, industry category.
* **User Personas**: Target users (e.g. Doctors vs Patients, Admins vs End-users).
* **Compliance / Security Needs**: HIPAA, SOC2, PCI-DSS requirements.

---

## 📤 Ye Kya Output Degi?

* Detailed **25-Point Domain-Specific Product Strategy** document.
* Information Architecture (IA) screen flow map.
* Domain-specific UX pattern recommendations (Command Palette, Split View, Sign-off Drawers).
* Target directives for Design, Security, and Engineering skills.

---

## 🤝 Dusri Skills Ke Saath Relation

* **Design Director**: Industry-appropriate visual tone directives pass karti hai (without relying on clichés like blue for finance).
* **Security Director**: High-trust data protection, BOLA/IDOR prevention, aur compliance requirements handoff karti hai.
* **Premium Web / Premium Flutter**: Framework-specific routing, deep links, aur multi-pane layout directives provide karti hai.

---

## 🧩 Master Orchestrator Mein Iska Role

* Master Orchestrator industry-heavy ya complex applications ke liye Phase 1 (Foundation) mein `domain-specific-skills-director` ko sabse pehle run karta hai.
* Iska strategy document baaki saare specialists ke product context ko dictate karta hai.

## 🚫 Ye Skill Kya Nahi Karegi?

* Ye har product ko generic SaaS landing page template mein force nahi karegi.
* Ye direct UI styling ya CSS variables code nahi likhti (woh `design-director` aur implementation skills ka kaam hai).
